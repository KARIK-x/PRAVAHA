Elliott Wave — candidate counts

Heuristic candidate counts derived from confirmed swings only. This is an interpretation with alternatives, never a guaranteed forecast. “Confirmed swings considered” is how many pivots the engine examined — it is not the number of wave counts found. The number of counts is the number of rows that follow. The period is applied before swings are found, so you can ask what a count looked like up to a chosen date; Same as chart range keeps the analysis on exactly the bars the chart shows, so a drawn candidate is always on-screen. Harmonic patterns — XABCD candidates

Published ratio bands (Gartley/Bat/Butterfly/Crab/Cypher) measured over confirmed swings. A band match is a candidate, not a confirmed pattern; the actual ratios used to accept it are shown. Tolerance 0 means the published ratios only; a positive value widens every band symmetrically and marks matches as approximate.

Index & relative strength

Stock-versus-index relative strength from stored historical series. The ratio is stock_close / index_close rebased to 100 at the first date present in both series (an inner join — missing dates are counted, never forward-filled); the excess return is the stock's window return minus the index's over the same aligned window. Indices come from the supplied published files — this is not a live feed. A security without enough aligned history is reported unavailable with the exact reason, never compared against a substitute index.

                Kronos — financial time-series foundation model

                Kronos (MIT licence) is an open financial foundation model trained on millions of daily candles. A tokenizer quantifies OHLC + volume + amount candles, an autoregressive transformer then samples future candle paths conditioned on a historical window. It forecasts from your stored history — it is not a live NEPSE feed and never replaces observed prices.

                Runtime status

                Model facts

                Official repository: shiyu-coder/Kronos · weights: NeoQuasar/Hugging Face · vendored model code (MIT) under vendor/kronos with its official regression suite — golden outputs matched at <1e-6 relative error on this machine.

                Limitations, measured honestly

                • Forecasts are sampled paths, not certainty: greedily-decoded output is reproducible but still a model sample.
                • Daily NEPSE volatility is small; measured benchmarks here show simple baselines (last-close, drift) can beat the model on MAE — run AI Forecaster → Evaluate vs baselines before trusting any symbol.
                • The model knows nothing about NEPSE circuit rules, corporate actions or news; its context is only past candles.
                • Context is capped at 512 bars by the official architecture.

                Average return by month of year

                Bars are the mean monthly return per calendar month over the stored range; the dashed line is the overall mean of those monthly means. Sample sizes and the full distribution are in the table below.

                Average return by weekday

                Mean close-to-close return grouped by day of week. NEPSE trades Sunday–Thursday; a weekday absent from the stored data is shown as a gap, never as a zero.

                Average return by quarter

                Compounded from the month returns above (Q1 = Jan–Mar … Q4 = Oct–Dec), then averaged across years. A year missing any month in a quarter is excluded from that quarter's mean — nothing is interpolated.
